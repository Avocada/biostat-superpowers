# Independent review: initial fresh-agent pilot

Scope: baseline_initial_snapshot and upgraded_initial_snapshot, reviewed after fixing the rubric and before reading follow-up outputs. Read-only inspection of both arms; no arm artifacts changed and no models rerun. Inspected reports, report-building code, analysis code, JSON/CSV results, decision logs, upgraded controller/memory/MCP evidence, and all 11 actual PNGs (five analytical figures per arm plus the upgraded MCP age histogram). Independently checked input hashes and raw cohort/event counts with read-only CSV inspection. HTML source/captions were inspected, but this review did not browser-test the interactive pages. Arm identity was visible, so this is independent, not blinded, review.

## Assessment

Both arms provide useful, qualified observational audits. Both recover identical crude and legacy-weighted point estimates and clearly decline causal identification. No critical numerical fabrication, materially incorrect displayed point estimate, or unsupported causal conclusion was found. Both are conditionally ready as exploratory audit deliverables, not publication-ready causal analyses. The small bootstrap counts and unresolved timing, missingness, ascertainment and dependence issues remain relevant.

The upgraded arm contributes useful missingness-indicator balance and source/runtime provenance. The baseline contributes a stronger follow-up ascertainment check and a timing-related feature-set sensitivity. Their overall scientific/visual quality is similar. The score difference below is descriptive reviewer judgment, not statistically established superiority or an effect attributable to integration.

## Material issues and actions

1. **Medium: weak bootstrap safeguards in both reusable scripts.** Baseline warning-bearing fits can still enter intervals; upgraded catches exceptions and reports failures but retains nonconverged warning-bearing fits and has no minimum successful fraction. These are implementation risks, not evidence that the current estimates are numerically wrong. Add warning/nonfinite checks, save replicate status and require review of failures before intervals. Both should present small-B intervals as preliminary and avoid interpreting their endpoint differences as performance gains. Baseline already explicitly notes Monte Carlo variation in its HTML.
2. **Medium: upgraded memory influence is overstated mechanically.** analysis.py records four facts, retrieves them, asserts selection usability and the words 'exploratory'/'within-day', and saves text. The contract/model specification and report labels remain explicitly coded. This establishes persistence, retrieval and a basic guard; it does not demonstrate that retrieved values generated or changed analysis choices. The report's 'retrieved scope/timing constrained labeling' is defensible as analyst process description, but should not be presented as experimentally demonstrated memory benefit or dynamic controller execution. No stale/conflicting-memory challenge is demonstrated in this initial snapshot.
3. **Medium: upgraded endpoint audit is less complete.** Add the baseline-discovered last-contact check, while retaining the correct caveat that this is an ascertainment question, not proof that 11 outcomes are wrong. Do not silently recode those records.
4. **Medium: distinguish encoded-value balance from missingness balance.** Upgraded correctly includes ADL missingness SMD 0.1806 in its HTML table. Its short headline '0 terms above 0.10' refers only to 72 encoded legacy terms. Preserve that scope when summarizing; neither all measured information nor all missingness is balanced.
5. **Low: standalone figure reuse.** Keep uncertainty-method captions attached, label missingness semantics for date fields, and use shape/line-style distinctions as well as color. These are presentation refinements, not numerical defects.

## Limits of comparison

These are single initial runs. Shared input/request does not eliminate agent stochasticity, implementation choices, unequal failed work or differing bootstrap counts. Both transcribe the legacy estimator rather than execute the original script unchanged. No fresh autonomous arm should be conflated with the earlier deterministic paired-script audit. No token, cost or speed conclusion is made here; this reviewer has not inspected telemetry. Scores cover scientific/reporting artifacts, with integrations scored separately. Follow-up outputs must be assessed as a distinct phase against the same criteria.

## Matched follow-up assessment

Reviewed baseline/ and upgraded/ followup.html source/text, FOLLOWUP.md, followup_results.json, context_sources.json, follow-up analysis code, both actual new comparison PNGs, and upgraded retrieval/append/workflow artifacts. No arm artifacts were changed, no models were rerun, and telemetry was not evaluated. Browser layout/interactivity was not tested.

**Scientific result: matched and correctly qualified.** The original and reduced adjustment variable lists and encoded-term lists match exactly across arms. Both remove only adld3p and urin1, keep cat2, keep all 5,735 patients and preserve other preprocessing/model choices. All six pairs of risks, RD, RR, clipping counts and maximum weights are numerically identical across arms (maximum difference 0 for the checked common fields). Reduced-minus-original contrasts also match exactly:

Both faithfully state that confounder deletion is a sensitivity analysis, not a causal repair; no new intervals are computed or borrowed from the initial run. Lack of new intervals is compliant with the bounded point-estimate task and is not penalized. Both assess balance of the omitted imputed variables on the original matrix, explaining that this cannot assess their unobserved values. ADL residual |SMD| rises to approximately 0.166. Baseline additionally separates retained-term maximum SMD from omitted-variable imbalance; upgraded reports all-original-term maximum SMD. These different diagnostic column labels explain the differing displayed maxima and are not numerical disagreement.

**Preservation independently verified:** every file in the baseline initial snapshot is byte-identical in the follow-up directory. Every upgraded initial-snapshot file is byte-identical except project-memory.sqlite3, whose change is authorized appending. Direct read-only SQLite comparison confirms all four old record payloads are unchanged, with exactly one added decision record. Original reports, code, input, results and figures are preserved in both arms.

**Reuse demonstrated in both arms:** both extract only saved function definitions from the original analysis AST, verify input provenance, fit two propensity models, and calculate the requested six contrasts rather than rerunning the full original analysis/bootstrap/report. Baseline uses ordinary saved code/results/decision files effectively; persistence benefits are not unique to SQLite memory.

**Upgraded memory evidence is materially stronger in this phase.** The successful lookup genuinely retrieves four initial-run records from the existing database; their IDs match the initial snapshot. An initial lookup using only the CSV hash returned unavailable-key issues. Reconstructing the stored composite input/contract fingerprint resolves those issues without altering old records. This is evidence of fingerprint-sensitive retrieval and honest recovery, not a demonstrated changed-data or conflict-handling experiment. The appended decision references all four existing records as dependencies, preserves analyst attribution, distinguishes user authorization from scientific approval, and records the unresolved gates. Retrieved sources are linked in context_sources.json and used for relevant checks. No new MCP calls or source discovery are claimed; cached MCP profile/source artifacts are reused. This supports upgrading memory fidelity from the initial phase's 2/3 to **3/3 for the bounded continuation**, and decision trace from 2/3 to **3/3**. It still does not prove automated substantive reasoning from memory, lower token use or scientific benefit over ordinary file reuse.

The new upgraded inferential controller run genuinely stops at evaluation/no_progress_threshold with evaluation pending and report_ready=false. Its original stopped causal workflow remains byte-identical. A separate bounded exploratory calculation has not been mislabeled completion of causal identification.

**Visual assessment:** both follow-up PNGs are clear, numerically faithful and suitable for the bounded report. Both now distinguish specifications through marker shapes as well as color, annotate point estimates, show appropriate null references and explicitly disclose no intervals. Baseline labels both clipping bounds and the RD/RR directions; upgraded explicitly names the two omitted variables and retained cat2. No overlapping or cut-off annotations were observed. Their follow-up visual fidelity and accessibility meet the strong anchor (3/3 for these figures); this does not retroactively change initial-report scores. Upgraded FOLLOWUP.md has an unescaped pipe in the 'Max |SMD|' table header, a minor Markdown formatting flaw; the HTML diagnostic table preserves the data. No material scientific or causal misstatement was found.

**Conclusion for follow-up:** both successfully answer the matched request with identical scientific results, effective reuse and preserved initial artifacts. Upgraded adds a verifiable structured retrieval/dependency trail; baseline achieves the same scientific computation with ordinary files. The difference is trace structure, not numerical accuracy or causal readiness. Initial scores remain phase-specific; no new aggregate 100-point score is assigned because the follow-up intentionally reuses cohort/missingness/identification work and requests no new uncertainty analysis. Token/cost/time claims require the separate telemetry assessment and cannot be inferred from 2,070 retrieved UTF-8 bytes.
